PRODUCT REQUIREMENTS DOCUMENT (PRD)

PROJECT TITLE: SocialSpark – Social Media Engagement Analytics &
Prediction System

PROJECT TYPE: Final-Year B.Tech CSE / Data Analytics Project

PROJECT GOAL: Build a complete end-to-end analytics platform that
analyzes historical social-media data, creates interactive dashboards,
predicts expected engagement for new posts using machine learning, and
generates data-driven content recommendations.

1.  PROJECT OVERVIEW

SocialSpark is a web-based Social Media Engagement Analytics and
Prediction System.

The system will: - Accept social-media datasets through CSV/Excel
upload. - Clean and preprocess the data using Python. - Store structured
data in MySQL/PostgreSQL. - Perform analytics using SQL and Python. -
Display interactive analytics dashboards. - Calculate important
engagement KPIs. - Analyze content, posting time, hashtags, captions,
reach, views, and audience behavior. - Predict expected engagement for a
new post using machine learning. - Generate recommendations based on
historical data patterns.

The project should look like a real industry Data Analytics product
rather than only a college dashboard.

2.  PROBLEM STATEMENT

Social-media platforms generate large amounts of performance data, but
raw metrics such as likes, comments, shares, views, reach, impressions,
and followers do not directly explain why some content performs
differently from other content.

Users need a single system that converts raw social-media data into
meaningful insights and helps them understand: - Which content performs
better? - Which posting times have higher engagement? - Which
platforms/categories perform better? - What factors are associated with
engagement? - What engagement could a new post potentially receive? -
What recommendations can be derived from historical data?

7.  MAIN MODULES

7.1 DATA UPLOAD MODULE

Features: - Upload CSV. - Upload Excel. - Display file name. - Display
number of rows and columns. - Validate required columns. - Show missing
values. - Show duplicate rows. - Show invalid data types. - Provide
cleaned-data download.

Required/Recommended fields: - post_id - platform - post_date -
post_time - content_type - content_category - followers - impressions -
reach - views - likes - comments - shares - saves - video_duration -
caption_length - hashtag_count

The application should work even if some optional columns are
unavailable. Required columns should be clearly documented.

7.2 DATA CLEANING MODULE

Use Python/Pandas to: - Remove duplicate rows. - Handle missing
values. - Standardize platform names. - Standardize content-type
names. - Convert dates and times. - Convert numeric columns to correct
data types. - Detect invalid negative values. - Handle outliers using a
documented method. - Create derived columns.

Derived columns: - total_engagement - engagement_rate - day_of_week -
month - year - posting_hour - weekend_flag - caption_length_bucket -
hashtag_count_bucket - video_duration_bucket

Suggested formula:

Total Engagement = Likes + Comments + Shares + Saves

Engagement Rate = Total Engagement / Reach × 100

If reach is unavailable, use a documented alternative such as
impressions or followers. Do not mix formulas without clearly labeling
them.

7.3 ANALYTICS MODULE

Calculate: - Total posts - Total views - Total impressions - Total
reach - Total likes - Total comments - Total shares - Total saves -
Average engagement - Median engagement - Average engagement rate -
Follower growth - Platform-wise engagement - Content-type engagement -
Category-wise engagement - Monthly engagement - Daily engagement -
Hourly engagement - Top-performing posts - Lowest-performing posts -
Reach-to-engagement relationship - Views-to-engagement relationship

7.4 SQL ANALYTICS

Create SQL queries for: - Total engagement by platform. - Average
engagement rate by platform. - Top 10 posts. - Monthly engagement
trend. - Engagement by content type. - Engagement by category. -
Engagement by weekday. - Engagement by hour. - Average reach by content
type. - Top hashtags if hashtag data is available. - Posts with
engagement above average. - Posts with unusually low engagement. -
Ranking posts using window functions. - Rolling monthly engagement where
applicable.

Use: - SELECT - WHERE - GROUP BY - HAVING - ORDER BY - JOIN - CASE -
CTEs - Window functions - Aggregate functions

8.  POWER BI / DASHBOARD DESIGN

Dashboard should be modern, clean, responsive, and professional.

Use filters: - Date range - Platform - Content type - Content category -
Day - Month

PAGE 1 – EXECUTIVE OVERVIEW

KPI cards: - Total Posts - Total Engagement - Average Engagement Rate -
Total Reach - Total Views - Total Followers

Charts: - Monthly engagement trend - Platform comparison - Content-type
comparison - Top-performing content - Engagement trend

PAGE 2 – CONTENT PERFORMANCE

Charts: - Engagement by content type - Engagement by category - Reach vs
engagement - Views vs engagement - Top 10 posts - Average engagement
rate by content type

Insights: - Which content type has higher engagement in the dataset? -
Which category has the highest average engagement? - Which posts are
outliers?

PAGE 3 – TIME ANALYTICS

Charts: - Engagement by weekday - Engagement by hour - Day × hour
heatmap - Monthly trend - Weekday vs weekend comparison

The system should identify historically strong posting windows without
presenting them as guaranteed future performance.

PAGE 4 – AUDIENCE & GROWTH

Charts: - Follower growth - Reach trend - Impressions trend - Engagement
trend - Audience segment analysis if demographic fields exist

PAGE 5 – TOP CONTENT

Table: - Post ID - Date - Platform - Content type - Category - Reach -
Views - Likes - Comments - Shares - Saves - Engagement rate

Allow sorting and filtering.

PAGE 6 – ML PREDICTION

Input form: - Platform - Content type - Category - Followers -
Expected/available reach - Expected/available views - Video duration -
Caption length - Hashtag count - Posting hour - Posting weekday -
Previous average engagement

Output: - Predicted engagement - Predicted engagement-rate estimate when
supported by the model - Model confidence/uncertainty information where
technically valid - Key input factors - Historical comparison

Important: Predictions must be presented as estimates, not guaranteed
results.

9.  MACHINE LEARNING MODULE

Goal: Predict expected engagement for a new social-media post.

Target: - Primary target: total_engagement OR - Alternative target:
engagement_rate

Models: 1. Linear Regression – baseline 2. Random Forest Regressor –
primary model 3. Optional Gradient Boosting/XGBoost

Preprocessing: - Encode categorical variables. - Handle missing
values. - Scale numerical features where required. - Split data into
training and testing sets. - Avoid data leakage.

Recommended split: - 80% training - 20% testing

For time-based datasets, preferably use a chronological split or
TimeSeriesSplit to reduce future-information leakage.

Evaluation: - MAE - RMSE - R²

Display: - Actual vs predicted chart - Feature importance - Evaluation
metrics

10. RECOMMENDATION ENGINE

The recommendation engine must be data-driven.

It can identify: - Historically high-performing posting windows. -
Content types associated with higher engagement. - Categories with
strong engagement. - Caption-length patterns. - Hashtag-count
patterns. - Video-duration patterns. - Platform-specific patterns.

Example output:

“Within the analyzed dataset, posts published during the 6–8 PM period
showed higher median engagement than other observed time periods.”

“Within this dataset, short-form video content had a higher median
engagement rate than image content.”

Do not present these observations as universal rules.
